## Decisions so far (rounds 1-2)
1. **Local subagent backend = the existing gateway + the verified PrismML Vulkan build**, not a new stack. Do not install any TurboQuant fork binary; use mainline KV rotation with `-ctk q8_0 -ctv q8_0` (V may drop to q5_1/q4_0 only after our own tool-call test).
2. **Models to fetch (C:, with SHA-256 from the Hugging Face API):** Ternary-Bonsai-2-9B `PQ2_0-MTP-Q8_0` (2.68 GB) as fast helper; Qwen3.5-9B Q4 as executor (thinking off) after a head-to-head against the existing abliterated Qwen3-4B; 4B Bonsai as always-on System 1 candidate. Bonsai-27B stays batch-only.
3. **Vulkan checks before trusting speed:** `llama-bench -ngl 0` vs `-ngl 99` on the 680M; confirm the Prism build has the integer-dot MMVQ path (issue #329) by comparing PTQ1_0 vs PQ2_0 token rates; do not use Vulkan DFlash2 for anything that needs determinism.
4. **Memory governor:** router-style start with `--models-max 2`, `--sleep-idle-seconds`, `-cram 1024`, free-RAM gate (model + KV + 3 GB), tiers by free RAM; fail closed.
5. **Secrets hygiene first:** rotate the GitHub token and the OpenCode server password; configs read `{env:VAR}`.
