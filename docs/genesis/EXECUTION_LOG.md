## 2026-11-07 - B1 follow-up: runtime install and removal (`hscl-cqhecs`)
- Decision: the default venv lives in the user's data directory (`$XDG_DATA_HOME/hscl/cqhecs/venv`), not `/opt/hscl/venvs/cqhecs`. Genesis 2.2 allows "a user-managed equivalent" and 2.5 forbids a privileged helper for something the user's account can do; a root-owned `/opt` venv would need one.
- Added `usr/share/hscl/cqhecs/requirements-cp314.txt` (7 dependency wheels plus the CQ-HECS 5.0.0 release wheel, every line `--hash=sha256:`; the cqhecs hash equals the release's `sha256sums.txt`) and `runtime.conf` (python 3.14, 64,525,947 bytes to download).
- `install-runtime`: refuses a Python other than 3.14 (exit 5, nothing changed); prints venv path and download size (61.5 MiB); without `--yes` (or an interactive "y") does nothing (exit 6); with `--yes` runs only `python3 -m venv` and `pip install --require-hashes --only-binary=:all: --no-input --disable-pip-version-check -r <file>`; on failure removes a venv it created itself. `uninstall-runtime --yes` removes only the venv; user data stays.
- Tests (red first, 13 now pass): hash-pin format, no foreign index/editable/VCS lines, size shown before action, exact pip flags via a stub interpreter, wrong Python refused, uninstall keeps user data. Full host suite 578 passed, 12 skipped. ShellCheck clean; `.deb` builds (3.6 KB, five payload files).
- **Not verified:** a real `install-runtime --yes` against the network on a real CPython 3.14 / Ubuntu 26.04 (the tests use a stub interpreter; the hashes were computed from downloaded wheels but a real pip install of them was not run); `cq-hecs doctor` of the 5.0.0 wheel; behaviour with less disk space than needed (no free-space check yet); other Python versions (pins are 3.14 only, by design); inclusion in the ISO.
